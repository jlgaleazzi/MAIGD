# Biplanes: Technical Architecture (crew contract)

Owner: orchestrator. Every agent reads this before writing code or data. If a task needs
something this contract doesn't cover, stop and report it in your handoff. Don't make it up.

## 0. Golden rules (these keep a local model's output buildable)
1. **Never hand-write Unity YAML** (`.unity`, `.prefab`, `.asset`, `.mat`, `.meta`).
   Scenes and prefabs are generated by the C# editor script `ProjectBuilder` (§6).
   Unity creates `.meta` files on import.
2. **Code finds content by path, never by GUID**: sprites come from `Resources.Load`,
   missions are JSON `TextAsset`s.
3. **No tags or physics layers.** Identify objects by component (`Team`, `IDamageable`).
4. **One class per file**, and the filename must match the class name. Namespace
   `Biplanes.<Area>`.
5. **Unity 6 LTS (6000.0.x), C# 9.** No external packages except `com.unity.inputsystem`
   and `com.unity.test-framework`.
6. Every tunable number lives in `Balance.json` or the mission JSON. No magic numbers in
   gameplay code.

## 3. Runtime model
- **Camera:** orthographic, size 5 (10 world units tall, 16:9 means about 17.8 wide).
  The **world scrolls**: `ScrollController` moves the camera right at `scrollSpeed`
  (world units/s) taken from the mission JSON. "Mission distance" = the camera's x.
- **Player** stays inside the camera rectangle minus a 0.5 margin. Moves with
  `Rigidbody2D` (Kinematic) and `MovePosition`.
- **Ground** sits at y = -4.5 and is drawn by `TerrainStrip` from the mission's
  `terrain` heights. Touching terrain, buildings or trees = instant 100% damage.
- **Physics:** 2D only. Every hittable object has a `Collider2D` set to **isTrigger**,
  and every moving object has a Kinematic `Rigidbody2D`. Collision logic lives in
  `OnTriggerEnter2D`.
- **Teams:** `enum Team { Player, Enemy, Neutral }` on the `TeamTag` component.
  Projectiles ignore their own team.

### Core interfaces and classes (create exactly these names)
```csharp
namespace Biplanes.Core {
  public enum Team { Player, Enemy, Neutral }
  public interface IDamageable { Team Team { get; } void ApplyDamage(float percent, DamageSource src); bool IsDead { get; } }
  public enum DamageSource { Bullet, Bomb, Flak, Collision }
  public static class GameEvents {            // plain C# events; UI and missions listen
    public static event System.Action<int> ScoreChanged;              // new total
    public static event System.Action<float> PlayerDamageChanged;     // 0..100
    public static event System.Action<int> BombsChanged;              // 0..7
    public static event System.Action<string, Team> EntityDestroyed;  // entityType, team
    public static event System.Action<string> ObjectiveCompleted;     // objective id
    public static event System.Action<bool, string> MissionEnded;     // won, reason
    // plus Raise* static methods for each event
  }
  public class GameBalance { /* fields mirror Balance.json; static Load() from Resources */ }
  public class SaveSystem { /* PlayerPrefs: "unlocked_mission" (int 1..5), "best_score_N" */ }
}
```
Scripts in Core/: `GameManager` (state machine: Menu, Briefing, Playing, Paused, Won,
Lost), `ScrollController`, `ScoreKeeper`, `TeamTag`, `Health` (implements IDamageable,
percent-based, raises events, death VFX hook).

### Player (Player/)
- `PlayerInput`: Input System, reading the keyboard directly with
  `Keyboard.current.wKey.isPressed` and so on. No `.inputactions` asset.
  W/A/S/D move, Space fires (hold to autofire at `fireRate`), Enter drops a bomb (one per
  key press).
- `PlayerPlane`: movement, takeoff state (mission 1 starts `onRunway: true`. The plane
  sits at the airfield until the player presses D or W, then climbs out), smoke trail at
  ≥ 70% damage, crash when damage reaches 100%.
- `BombBay`: holds up to 7 bombs and starts each mission full. Bombs fall under gravity
  and inherit the plane's x-velocity.

### Enemies (Enemies/), one class each
`FighterAI`, `BomberAI` (has `targetX`: reaching it = mission fail when an objective
says so), `AAAGun` (fires flak bursts up at the player's predicted position, ground-bound,
damaged by `DamageSource.Bomb` only), `ZeppelinAI` (hull plus N `ZeppelinTurret` children;
the hull only takes damage after all turrets are destroyed, or `hullVulnerableEarly` in
Balance), `BarrageBalloon`, `HealthBalloon` (pickup), `StaticObstacle` (building/tree).
All of them are spawned by `MissionRunner` from the mission JSON.

### Weapons (Weapons/)
`Bullet`, `Bomb`, `FlakShell`, `Projectile` (base class: speed, team, damage, lifetime),
`ObjectPool<T>` (generic). Nothing calls `Instantiate` in the update loop.

### Missions (Missions/)
- `MissionData` (`[Serializable]` classes matching the JSON in §5, parsed with `JsonUtility`).
- `MissionRunner`: loads `Resources/Missions/mission_0N`, spawns entries when camera x ≥
  `atX`, tracks objectives, raises `MissionEnded`.
- `ObjectiveTracker`: evaluates the objective types in §5.

### UI (UI/), built with uGUI from code, specified in docs/UI_SPEC.md
`HudView` (damage bar, smoke-warning tint at 70%, bomb icons ×7, score, objective text),
`MainMenuView` (mission select limited to `unlocked_mission`), `BriefingView`,
`PauseView` (Esc), `ResultView` (win/lose, score, retry, next).

## 4. Balance.json (defaults; mechanics creates it, mission-design tunes it)
```json
{
  "player": { "speed": 5.0, "fireRate": 8.0, "bulletSpeed": 14.0, "bulletDamage": 25.0,
              "bombCapacity": 7, "bombDamage": 100.0, "smokeThreshold": 70.0 },
  "damageTaken": { "fighterBullet": 8.0, "flak": 15.0, "bomberGunner": 10.0, "zeppelinTurret": 12.0, "collision": 100.0 },
  "healthBalloonRestore": 30.0,
  "enemyHealth": { "fighter": 25.0, "bomber": 200.0, "aaa": 100.0, "barrageBalloon": 50.0, "zeppelinTurret": 75.0, "zeppelinHull": 1000.0, "enemyBase": 100.0 },
  "score": { "fighter": 100, "barrageBalloon": 75, "aaa": 150, "zeppelinTurret": 200, "bomber": 500, "enemyBase": 1000, "zeppelin": 2500 },
  "hullVulnerableEarly": false
}
```
Enemy health is in damage points where the player bullet deals `bulletDamage`, so a
fighter dies in 1 hit, a bomber in 8, and the hull in 40. Player damage is a percentage.

## 5. Mission JSON schema (`Resources/Missions/mission_0N.json`)
```json
{
  "id": 1,
  "title": "Destroy Incoming Airplanes",
  "briefing": "Wave of enemy fighters inbound. Take off and shoot them all down.",
  "scrollSpeed": 2.0,
  "length": 300.0,
  "playerStart": { "x": -6.0, "y": -4.0, "onRunway": true },
  "background": "farmland",
  "terrain": [ { "atX": 0, "height": 0.0 }, { "atX": 120, "height": 1.5 } ],
  "spawns": [
    { "atX": 10,  "type": "fighter",        "y": 2.0, "count": 3, "spacing": 1.5, "pattern": "sine",   "id": "" },
    { "atX": 60,  "type": "aaa",            "y": 0.0, "count": 1, "spacing": 0,   "pattern": "static", "id": "" },
    { "atX": 80,  "type": "healthBalloon",  "y": 1.0, "count": 1, "spacing": 0,   "pattern": "drift",  "id": "" },
    { "atX": 90,  "type": "building",       "y": 0.0, "count": 2, "spacing": 2.0, "pattern": "static", "id": "" }
  ],
  "objectives": [
    { "id": "kill_all_fighters", "type": "destroyAllOfType", "targetType": "fighter", "targetId": "", "failAtX": -1 }
  ]
}
```
- `type` must be one of: `fighter`, `bomber`, `aaa`, `zeppelin`, `barrageBalloon`,
  `healthBalloon`, `building`, `tree`, `enemyBase`, `airfield`, `playerHQ`.
- `pattern` must be one of: `static`, `straight`, `sine`, `dive`, `escort` (follows the
  nearest entity with `id` == `escortOf`), `drift`.
- Optional per-spawn fields: `escortOf` (string), `targetX` (float, for bomber/zeppelin).
- Objective `type` must be one of:
  - `destroyAllOfType`: every spawned entity of `targetType` destroyed.
  - `destroyById`: the entity with `id` == `targetId` destroyed. If `failAtX` ≥ 0 and the
    target reaches that x (bomber/zeppelin arriving at its target), the mission is lost.
  - `bombTarget`: the entity with `targetId` destroyed by `DamageSource.Bomb`.
  - `surviveToEnd`: camera reaches `length`.
- The mission is won when all objectives are complete and lost when player damage reaches
  100% or any `failAtX` triggers.
- `y` is the height above the local terrain, in world units.

## 6. ProjectBuilder (editor automation)
`Biplanes.EditorTools.ProjectBuilder` with static methods, each also a menu item under
`Biplanes/`:
- `BuildScenes()`: creates `Assets/Biplanes/Scenes/MainMenu.unity` and `Game.unity` from
  code (camera, managers, UI canvas, EventSystem) and adds them to Build Settings.
- `ConfigureProject()`: sets the sprite import settings for everything under
  `Resources/Sprites` (Sprite 2D, PPU 100, Bilinear filter, no compression for line art), active input handling = Input System, and
  company/product name.
- `BuildWebGL()`, `BuildWindows()`, `BuildMac()`: build into `Biplanes/Builds/<target>/`.
- `BuildAll()`: runs ConfigureProject, then BuildScenes, then all three builds. Exit code
  ≠ 0 on failure.

Call it from the shell with `tools/unity.sh <method>` (see tools/unity.sh).

## 7. Definition of Done (every code task)
- Compiles. If Unity is available, `tools/unity.sh compile` returns 0. If not, QA
  statically checks namespaces, usings and the API names against this document.
- No `Debug.Log` spam in the update loop. No `FindObjectOfType` per frame.
- Public fields are `[SerializeField] private`, or read from GameBalance.
- At least one EditMode test for every piece of pure logic (damage math, objective
  evaluation, JSON parsing, save system).
- Handoff note written.
