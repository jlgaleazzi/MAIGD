## 4. API & Compile Error Issues

### P1: ObjectiveTracker.Start() — missing parameter type (line 93)
```csharp
public void Start(objectiveEntries, float cameraX) {
```
The first parameter `objectiveEntries` has no type annotation. This will not compile. It should be:
```csharp
public void Start(ObjectiveEntry[] objectiveEntries, float cameraX) {
```

### P1: BarrageBalloon.cs — unused URP import (line 2)
```csharp
using UnityEngine.Rendering.Universal;
```
This file does not reference any type from `UnityEngine.Rendering.Universal`. If Unity is built without the URP package installed, this produces a compile error. Either remove the using or use it somewhere.

### P2: ScoreKeeper.OnMissionEnded() calls non-existent SaveSystem method (line 90)
```csharp
SaveSystem.SetBestScore(missionIndex, CurrentScore);
```
`SaveSystem` has `SaveBestScore()` (PascalCase), but the call uses `SetBestScore()` (camelCase). Same for `SetUnlockedMission`.

### P2: Health.cs — Bomb multiplier uses fighterBullet instead of dedicated value (line 98)
```csharp
case DamageSource.Bomb:
    return balance.damageTaken.fighterBullet; // bomb = full percent
```
Bomb damage should use a different multiplier or the bombDamage field from balance. Currently it returns `fighterBullet` (8.0), meaning bombs apply `percent * 8` before clamping to 100. While the result is functionally correct (clamped at 100%), the design contradicts GDD which treats bomb damage as a percentage that should be used directly.
