DESIGN CHOICES:
- Which wins are delayed: only the kill paths. HandleObjectiveComplete("all_objectives") comes from EntityDestroyed and HandleObjectiveComplete("bomb_target") comes from a bombed EnemyBase; both wait killWinDelaySeconds. A "survive_to_end" win at the map end still opens the result at once (delay 0), as before. Losses are unchanged: the player crash keeps CrashFallSeconds, and objective or map-end failures stay instant.
- Can't lose: GameManager.SetState already refuses any end once the mission is Won. MissionRunner's _missionEnded stops CheckTargetsReached, map end and a second HandleObjectiveComplete. A crash during the delay plays the wreck visually and calls LoseMission, which is ignored.
- Controls: MissionRunner.OnMissionEnded(won) keeps the input and scroll alive and sets a deadline at realtimeSinceStartup + delay. Update calls TickWinControlEnd(realtime), which runs EndPlayerControl once at the deadline, the same moment GameManager's coroutine opens the result (WaitForSecondsRealtime). Next or teardown clears a pending deadline.
- Ram damage uses DamageSource.Bullet. In enemy mode, Health only treats Collision and PlaneCollision as fatal, so this applies the 250 points as given. A new DamageSource would have needed a fallback branch for the player in Health.
- Grace order: a fighter touched during the grace window still dies, as before. A bomber touched during grace takes no ram, so its several hitboxes and the same pass count as one ram. A bomber touched right after a fighter, inside the grace window, is also not rammed.
