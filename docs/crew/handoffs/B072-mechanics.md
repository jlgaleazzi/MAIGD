SUMMARY: Flying into a barrage balloon pops it (the balloon gets DamageSource.Collision, so it raises EntityDestroyed("barrageBalloon"), scores 75 and counts toward objectives like a shot-down balloon) and costs the player 50 raw via DamageSource.PlaneCollision / resistance 1.5 = 33.3%. This shares the PlaneCollisionGraceSeconds window with fighter and bomber contact, so one pass costs it once; three hits crash. Balloons now have 100 HP (4 bullets or 1 bomb).
FOUND: before this change the balloon was never fatal. Nothing applied damage on contact, and BarrageBalloon.Awake set `_rb.simulated = false`, which takes its collider out of the physics world. So in a real run, bullets, bomb bursts (OverlapCircle) and the player's contact could not register on it, and its drift MovePosition did nothing. It is now simulated (still Kinematic). Balloons become shootable and bombable in play, drift as coded, and collide as specified. No other code had a fatal path for balloons, so there was nothing to remove. No existing test asserted balloon HP 50 or a fatal balloon, so no stale tests needed updating.
NOTES: The player's collision damage keeps the PlaneCollision source, so resistance and the Health path are unchanged. The `percent` argument is barrageBalloonCollision / planeCollision (1.0 with today's Balance), so the raw hit equals barrageBalloonCollision. A balloon touched inside the grace window (after another balloon or a fighter) still pops, but the player takes no extra damage, the same as fighters. Enemy bullets, flak and enemy bombs skip the balloon (Team.Enemy, own team). Health.cs and DamageSource.cs were not changed.
